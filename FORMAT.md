# On-disk format (v2 draft)

The device contains two superblock slots followed by append-only records. Records are header, payload, and alignment padding. The record header contains magic, version, kind, payload length, generation, and a BLAKE3-derived checksum. Object IDs use separate BLAKE3 domains (`cairn/chunk/v1` and `cairn/manifest/v1`). Version 2 readers reject version 1 devices; migration is not implicit. Every offset and length is checked before arithmetic or allocation. The current erasure-coding profile is explicitly 6 data shards plus 4 parity shards; shard checksums are part of the trusted descriptor used for repair, and the descriptor identity is bound to the complete expected-checksum set.

The durable commit order is data records, `flush_data`, root commit, `flush_data`, older superblock slot, and `flush_all`. Recovery accepts the highest complete valid generation and falls back to an older complete slot when the newest published root is corrupt. A checkpoint is only a scan shortcut; a full scan remains authoritative.
